# 心理数据分析项目面试速查

## 一、项目一句话

这是一个面向心理调查数据的数据分析与用户画像平台，完成了从数据导入、清洗、
特征工程、聚类分类、画像生成、PDF 报告到可视化展示的完整闭环。

技术栈：

```text
Vue 3 + Pinia + Element Plus + ECharts
Flask + SQLAlchemy + MySQL/SQLite
JWT + bcrypt + RBAC
Pandas + scikit-learn
ReportLab + pytest
```

## 四、整体架构

```text
浏览器
  → Vue Router / Pinia
  → Axios 携带 Bearer Token
  → Vite 代理 /api
  → Flask Blueprint
  → JWT + RBAC 权限校验
  → Service 业务层
  → SQLAlchemy / scikit-learn
  → MySQL 或 SQLite
  → JSON 返回
  → ECharts 渲染
```

后端分层：

```text
API 路由层：接收请求、返回 JSON
Service 层：编排业务流程
ML 层：特征工程、聚类、分类
Model 层：SQLAlchemy 数据库模型
Utils 层：权限装饰器
```

## 五、必须会画的请求流程

以管理员打开数据概览为例：

1. 用户登录，后端校验 bcrypt 密码并生成 JWT。
2. 前端保存 Token，Axios 自动在请求头添加 Bearer Token。
3. 前端调用 `/api/viz/overview`。
4. 权限装饰器从 JWT 中取 `user_id`，再查数据库确认用户和角色。
5. `VisualizationService` 读取数据并补齐风险和年龄段。
6. 后端统计风险、性别、年龄和国家分布。
7. 返回 JSON，ECharts 渲染中文图表。

## 六、面试高频问题

### 1. 为什么要做这个项目？

回答重点：

- 心理调查数据字段多、缺失多、格式不统一。
- 单纯做表格管理价值有限。
- 希望完成从数据处理到分析输出的闭环。
- 同时练习后端权限、数据库、数据分析和前端可视化。

### 2. 为什么使用 Flask？

> 项目规模不大，业务流程清晰，Flask 比较轻量，Blueprint 和应用工厂便于按模块组织。
> 如果重新选择，FastAPI 在异步、类型约束和 OpenAPI 文档方面更有优势，但 Flask
> 的生态更成熟，也足够支撑当前功能。

### 3. JWT 登录流程是什么？

1. 用户提交用户名或邮箱和密码。
2. 后端使用 bcrypt 校验密码。
3. 生成 access token 和 refresh token。
4. 前端通过 Axios 在请求头携带 access token。
5. 后端通过 `@jwt_required()` 校验 Token。

### 4. 为什么权限不能只放在前端？

> 前端路由权限只能控制页面是否显示，用户仍然可以直接调用接口。后端必须重新校验，
> 否则修改前端代码或使用 Postman 就能越权。因此我在 Flask 增加了 RBAC 装饰器，
> 并在报告和自评接口中增加对象级所有权判断。

### 5. 为什么不直接相信 JWT 中的角色？

> JWT 中的角色可能过期。例如用户登录后，管理员将其禁用或调低权限，但旧 Token
> 在有效期内仍然存在。因此装饰器只从 JWT 中获取 `user_id`，角色的当前状态每次
> 都从数据库重新读取。

### 6. `auth_required` 和 `roles_required` 区别？

- `auth_required`：只要登录且账号有效即可访问。
- `roles_required('admin', 'analyst')`：除登录外，还必须属于指定角色。

### 7. 为什么注册接口不能再接收 `role`？

> 最初公开注册允许客户端传角色，恶意用户可以注册成管理员。修复后公开注册固定写入
> `user`，管理员和分析师必须通过受控的初始化脚本或管理员操作创建。

### 8. 如何做对象级权限？

> 角色权限只能回答“是不是管理员”，对象级权限还要回答“这条数据是不是你的”。
> 报告表记录 `user_id`，普通用户查询列表时强制过滤本人，下载时再次校验所有者。
> 自评详情接口也会检查 `record.user_id`。

### 9. Excel 上传为什么曾经失败？

> 接口允许上传 xlsx，但服务层始终调用 `pd.read_csv`。修复后按扩展名分发：
> CSV 使用 `read_csv`，xlsx/xls 使用 `read_excel`。

### 10. 原始数据没有风险等级，图表为什么有数据？

> 导入后使用可解释规则生成风险分层，并统一生成年龄段。对于历史数据，初始化脚本会
> 回填缺失字段；读取数据时也会再做一次派生，保证旧数据库可以兼容。

### 11. 为什么性别要先归并？

> 原始数据有 M、male、f、Female、Trans woman、queer 等几十种写法。如果不归并，
> 饼图会产生大量单样本分类。系统将展示值归并为男、女、非二元/流性、
> 其他/不愿透露四类。

### 12. KMeans 的 K 怎么选？

> 在 2 到 7 的范围内分别训练 KMeans，比较 silhouette score，选择轮廓系数最高的
> K。KMeans++ 用于优化初始中心点，降低陷入局部最优的概率。

### 13. 为什么使用 RandomForest？

> 心理调查主要是中小规模表格数据，RandomForest 对缺失值和异常值比较稳健，能够
> 输出特征重要性，也支持并行训练。项目使用 GridSearchCV 调参，并保存 accuracy、
> precision、recall、F1、混淆矩阵和特征重要性。

### 14. 模型可信度有什么不足？

> 当前风险标签主要来自可解释规则，不是外部临床金标准。因此模型更接近教学和流程
> 验证，不能用于临床诊断。后续应使用 PHQ-9、GAD-7 等量表分数作为独立标签，并
> 增加时间切分、外部验证、校准和公平性分析。

### 15. 为什么报告要有独立元数据表？

> PDF 文件本身只保存文件名，无法可靠知道谁生成、谁有权限下载。新增 `report_records`
> 记录用户、文件名、类型和时间，实现报告列表过滤和下载所有权校验。

### 16. 数据量大了怎么办？

> 当前分析限制 2,000 条，是为了控制同步请求耗时。演进方向是把分析改成 Celery
> 异步任务，记录任务进度和结果；数据查询增加索引、数据集批次和快照；再根据真实
> 数据规模决定是否使用 DuckDB、ClickHouse、Parquet 或 Spark，不会为了技术名词
> 直接上大数据组件。

### 17. 项目最难的部分是什么？

> 不是调用 KMeans 或 RandomForest，而是把权限、数据质量和对象归属做完整。
> 机器学习代码几十行就能运行，但越权、Excel 导入、无标签数据和报告归属都是
> 实际使用中才会暴露的问题。

### 18. 如果再给你一周，最先做什么？

1. 增加不可篡改的审计日志。
2. 增加组织和项目级数据隔离。
3. 把分析改成 Celery 异步任务。
4. 用真实量表分数替代规则风险标签。

## 七、四个真实难点故事

### 故事一：角色提升漏洞

问题：注册接口接受客户端 `role`。

处理：

- 注册固定为 `user`。
- 新增服务端权限装饰器。
- 权限从数据库读取。
- 补充越权测试。

结果：普通用户直接调用数据接口返回 `403`。

### 故事二：Excel 上传失败

问题：接口允许 xlsx，但服务层只调用 `read_csv`。

处理：

- 根据扩展名分发读取器。
- 增加 CSV 与 XLSX 测试。
- 同时修复单行数据被 3σ 清理删除的问题。

### 故事三：数据概览为空

问题：survey.csv 没有风险等级和年龄段，图片只能显示 0 或空白。

处理：

- 增加可解释风险派生。
- 统一年龄段。
- 归并自由文本性别。
- 增加历史数据回填。

结果：1,258 条数据可以正常展示分析结果。

### 故事四：报告越权

问题：报告没有所有者，任何登录用户都可能看到或下载其他人的报告。

处理：

- 新增报告元数据表。
- 列表按用户过滤。
- 下载校验所有者。
- 普通用户只能生成个人报告。
