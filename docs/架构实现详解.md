# 项目架构实现详解

## 一、先记住总链路

```text
Vue 页面
→ Pinia
→ Axios
→ Vite / Nginx /api 代理
→ Flask Blueprint
→ JWT + RBAC
→ Service
→ SQLAlchemy / scikit-learn
→ MySQL 或 SQLite
→ JSON
→ Axios 响应拦截器
→ Pinia / Vue
→ ECharts
```

向下是请求，返回时方向相反。

## 二、Vue 层

### 作用

Vue 负责：

- 展示页面。
- 处理表单和按钮。
- 调用 API。
- 保存页面状态。
- 使用 ECharts 渲染图表。

项目中的页面位于：

```text
frontend/src/views/
```

例如：

```text
login/index.vue              登录
dashboard/index.vue          数据概览
data/index.vue               数据管理
analysis/index.vue           特征分析
classification/index.vue     分类预测
profiles/index.vue           用户画像
report/index.vue             报告管理
self-assessment/index.vue    心理自评
```

### 页面如何调用接口

页面不会直接写 Axios 请求，而是调用 `src/api` 中的函数。

例如数据概览：

```javascript
import { getOverview } from '@/api/visualization'

const fetchData = async () => {
  const res = await getOverview()
  if (res.code === 200) {
    overviewData.value = res.data
  }
}
```

`getOverview` 返回的是一个 Promise，真正的 HTTP 请求由 Axios 发出。

## 三、Pinia 层

### 作用

Pinia 保存跨页面共享状态。

项目中主要保存：

```text
Token
用户信息
用户角色
登录状态
```

代码位于：

```text
frontend/src/store/modules/user.js
```

核心状态：

```javascript
const token = ref('')
const userInfo = ref(null)
```

派生状态：

```javascript
const userRole = computed(() => userInfo.value?.role || '')
const isLoggedIn = computed(() => !!token.value)
```

登录动作：

```javascript
const loginAction = async (credentials) => {
  const res = await login(credentials)

  if (res.code === 200) {
    setUserToken(res.data.access_token)
    setUserInfo(res.data.user)
    return res
  }
}
```

登录成功后：

```text
Token 写入 Pinia 和 Cookie
用户信息写入 Pinia
路由根据 role 跳转首页
```

## 四、Axios 层

### 作用

Axios 统一处理：

- API 基础地址。
- 请求超时。
- Bearer Token。
- 响应结构。
- 401 登录失效。
- PDF Blob 下载。

代码位于：

```text
frontend/src/utils/request.js
```

### Axios 实例

```javascript
const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  timeout: 120000,
  headers: {
    'Content-Type': 'application/json'
  }
})
```

### 请求拦截器

```javascript
const token = getToken()

if (token) {
  config.headers['Authorization'] = `Bearer ${token}`
}
```

这样所有使用该实例的请求都会自动携带 JWT。

### 响应拦截器

后端统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

Axios 会检查 `code`：

- `200`、`201`：成功。
- 其他：显示错误提示。
- `401`：跳转登录页。
- Blob：直接返回 PDF 文件数据。

## 五、Vite 开发代理

开发时前端是：

```text
http://localhost:3000
```

后端是：

```text
http://localhost:5000
```

Axios 请求 `/api/...`，Vite 会转发到 Flask。

配置位于：

```text

```

```javascript
server: {
  port: 3000,
  proxy: {
    '/api': {
      target: 'http://localhost:5000',
      changeOrigin: true
    }
  }
}
```

生产环境由 Nginx 完成相同代理。

## 七、Flask Blueprint

Blueprint 是路由分组，不负责复杂业务。

例如：

```python
viz_bp = Blueprint('viz', __name__)

@viz_bp.route('/overview', methods=['GET'])
@roles_required('admin', 'analyst')
def get_overview():
    data = VisualizationService.get_overview_stats()

    return jsonify({
        'code': 200,
        'message': '获取成功',
        'data': data
    }), 200
```

路由层只做：

1. 接收参数。
2. 调用 Service。
3. 返回 JSON。
4. 捕获异常。

## 八、JWT 认证

登录接口位于：

```text
backend/app/api/auth.py
```

### 登录步骤

1. 读取用户名和密码。
2. 按用户名或邮箱查询 User。
3. 使用 bcrypt 校验密码。
4. 检查账号是否禁用。
5. 更新最后登录时间。
6. 生成 access token 和 refresh token。

```python
access_token = create_access_token(
    identity=str(user.id),
    additional_claims={
        'username': user.username,
        'role': user.role
    }
)
```

返回：

```text
access_token：访问接口
refresh_token：刷新访问令牌
```

### 前端保存

Pinia 保存用户信息，Cookie 保存 Token。

### 后续请求

Axios 自动添加：

```http
Authorization: Bearer <access_token>
```

### 登录即访问

```python
@auth_required
```

### 指定角色访问

```python
@roles_required('admin', 'analyst')

    ...
```

### 装饰器内部流程

```python
user_id = int(get_jwt_identity())
user = db.session.get(User, user_id)

if not user or not user.is_active:
    return 401

if allowed_roles and user.role not in allowed_roles:
    return 403

g.current_user = user
```

为什么不直接相信 JWT 中的角色？

> 因为用户登录后角色可能发生变化，账号也可能被禁用。每次都按 `user_id`
> 查询数据库，可以保证权限是当前状态，而不是旧 Token 中的状态。

## 十、对象级权限

角色权限只能回答：

```text
你是不是管理员？
```

对象级权限还要回答：

```text
这条数据是不是你的？
```

例如报告下载：

```python
record = ReportRecord.query.filter_by(filename=safe_filename).first()

if (
    g.current_user.role not in ['admin', 'analyst']
    and record.user_id != g.current_user.id
):
    return 403
```

报告列表也会过滤：

```python
query = ReportRecord.query

if g.current_user.role not in ['admin', 'analyst']:
    query = query.filter_by(user_id=g.current_user.id)
```

## 十七、错误处理

统一响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

常用错误码：

```text
400 参数错误
401 未登录或 Token 无效
403 已登录但无权限
404 资源不存在
500 服务器错误
```

JWT 异常由统一回调处理：

```text
Token 过期
Token 无效
缺少 Token
```

## 十九、当前实现的边界

- Flask 分析和 PDF 仍是同步执行。
- Celery 和 Redis 只有配置，没有真实任务。
- 分析限制 2,000 条。
- 模型标签主要来自规则派生。
- 报告保存在本地目录。
- 没有完整审计和组织级隔离。
- 没有高并发压测数据。

面试时必须主动说明这些边界，不能把未来计划说成已经完成。

## 二十、面试口述版本

> 项目是前后端分离架构。前端由 Vue 管理页面，Pinia 保存 Token、用户信息和角色，
> Axios 统一添加 JWT 并处理响应。请求经过 Vite 或 Nginx 代理到 Flask Blueprint，
> 权限装饰器从 JWT 获取用户 ID 并查询数据库确认角色，报告和自评还会做所有权校验。
> 路由不直接写复杂业务，而是调用 Service。数据操作通过 SQLAlchemy 访问 MySQL 或
> SQLite，分析任务通过 Pandas 和 scikit-learn 完成 KMeans 聚类和 RandomForest
> 分类，模型使用 pickle 持久化。最终统一返回 JSON，前端再通过 ECharts 渲染。
> 当前分析同步执行，Celery 异步化属于下一阶段。
